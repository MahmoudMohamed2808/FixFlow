# خطة مشروع: نظام إدارة الصيانة (CMMS)

**النوع:** تطبيق ويب
**التقنيات:** Laravel + Livewire
**الغرض:** مشروع شغل حقيقي لشركة

---

## 1. نظرة عامة على المشروع

نظام يساعد الشركة على:
- تتبع كل الأصول/المعدات وحالتها
- إدارة أوامر الشغل (صيانة وقائية وعطل)
- جدولة الصيانة الدورية تلقائيًا
- إدارة المخزون وقطع الغيار
- متابعة أداء الفنيين
- إصدار تقارير عن التكلفة ووقت التعطل

---

## 2. التقنيات المستخدمة (Tech Stack)

| الجزء | التقنية |
|---|---|
| Backend | Laravel (أحدث إصدار LTS) |
| Frontend | Livewire + Blade + Alpine.js |
| التنسيق | Tailwind CSS |
| قاعدة البيانات | MySQL |
| المصادقة | Laravel Breeze / Fortify |
| الصلاحيات | Spatie Laravel-Permission |
| الجدولة التلقائية | Laravel Task Scheduler + Queues |
| الإشعارات | Laravel Notifications (Database + Email) |
| التقارير/PDF | barryvdh/laravel-dompdf أو maatwebsite/excel للتصدير |
| رفع الملفات | Laravel Storage (public/local disk) |
| الاختبار | PHPUnit / Pest |

## 3. تصميم قاعدة البيانات (ERD)

### الجداول الرئيسية

**roles**
- id (PK)
- name

**users**
- id (PK)
- name, email, password
- role_id (FK -> roles)
- department_id (FK -> departments)
- phone
- is_active (boolean)
- timestamps

**departments**
- id (PK)
- name
- timestamps

**locations**
- id (PK)
- name
- department_id (FK -> departments)
- parent_id (FK -> locations, nullable) — للتسلسل الهرمي (مبنى > دور > غرفة)
- timestamps

**asset_categories**
- id (PK)
- name
- parent_id (FK -> asset_categories, nullable)
- timestamps

**assets**
- id (PK)
- name
- serial_number (unique)
- category_id (FK -> asset_categories)
- location_id (FK -> locations)
- purchase_date
- warranty_expiry
- status: enum(operational, under_maintenance, broken, retired)
- manufacturer, model
- image (nullable)
- created_by (FK -> users)
- timestamps, soft deletes

**work_orders**
- id (PK)
- code (unique, auto-generated مثل WO-0001)
- asset_id (FK -> assets)
- type: enum(preventive, corrective)
- priority: enum(low, medium, high, urgent)
- status: enum(open, assigned, in_progress, completed, cancelled)
- description (text)
- reported_by (FK -> users)
- assigned_to (FK -> users, nullable)
- schedule_id (FK -> preventive_schedules, nullable)
- scheduled_date
- started_at, completed_at
- cost (decimal, nullable)
- timestamps, soft deletes

**preventive_schedules**
- id (PK)
- asset_id (FK -> assets)
- title
- frequency_type: enum(daily, weekly, monthly, yearly, usage_based)
- frequency_value (int)
- last_generated_date
- next_due_date
- is_active (boolean)
- timestamps

**spare_parts**
- id (PK)
- name, code (unique)
- unit (قطعة، لتر، متر...)
- quantity_in_stock
- minimum_quantity
- unit_price (decimal)
- supplier_id (FK -> suppliers, nullable)
- timestamps

**work_order_parts** (جدول pivot بحقول إضافية — يُعامل كـ Model مستقل)
- id (PK)
- work_order_id (FK -> work_orders)
- spare_part_id (FK -> spare_parts)
- quantity_used
- unit_cost (decimal)
- timestamps

**suppliers**
- id (PK)
- name, phone, email, address
- timestamps

**downtime_records**
- id (PK)
- asset_id (FK -> assets)
- work_order_id (FK -> work_orders, nullable)
- start_time, end_time
- duration_minutes (محسوبة)
- timestamps

**work_order_attachments** (اختياري - لصور/ملفات الأعطال)
- id (PK)
- work_order_id (FK -> work_orders)
- file_path
- timestamps

**work_order_comments** (اختياري - تعليقات على أمر الشغل)
- id (PK)
- work_order_id (FK -> work_orders)
- user_id (FK -> users)
- comment (text)
- timestamps

**activity_logs** (اختياري - تتبع من عمل إيه)
- id (PK)
- user_id (FK -> users)
- action
- model_type, model_id
- timestamps

### العلاقات الأساسية
- role hasMany users
- department hasMany locations, hasMany users
- location hasMany assets, belongsTo parent (self)
- asset_category hasMany assets, belongsTo parent (self)
- asset belongsTo category, belongsTo location, hasMany work_orders, hasMany preventive_schedules, hasMany downtime_records
- work_order belongsTo asset, belongsTo reportedBy (user), belongsTo assignedTo (user), hasMany work_order_parts, hasOne downtime_record
- preventive_schedule belongsTo asset, hasMany work_orders (المولّدة منه)
- spare_part belongsTo supplier, hasMany work_order_parts
- work_order_parts belongsTo work_order, belongsTo spare_part

### قرارات معمارية يجب حسمها قبل البدء
- **الصلاحيات:** استخدام Spatie Permission بدل enum بسيط في users، عشان مرونة أكتر (roles: Admin, Supervisor, Technician, Viewer)
- **Soft Deletes:** على assets و work_orders على الأقل (عشان محدش يمسح بيانات تاريخية بالغلط)
- **Multi-tenancy:** لو الشركة عندها أكتر من فرع منفصل تمامًا، محتاجين نضيف tenant_id من الأول (قرار صعب تغييره لاحقًا)

## 4. مراحل تنفيذ المشروع (Roadmap)

### المرحلة 0: الإعداد (Setup) — يوم إلى يومين
- تثبيت Laravel + Livewire + Tailwind
- إعداد قاعدة البيانات والـ .env
- تثبيت Laravel Breeze للمصادقة
- تثبيت Spatie Permission
- إعداد Git repository

### المرحلة 1: الأساسيات (Core Foundation) — أسبوع تقريبًا
- Migrations لكل الجداول أعلاه
- Models + العلاقات (Relationships)
- Seeders (بيانات تجريبية: أقسام، مواقع، تصنيفات)
- نظام تسجيل الدخول + الأدوار والصلاحيات
- تصميم الـ Layout الأساسي (Sidebar, Navbar, Dashboard فاضي)

### المرحلة 2: إدارة الأصول (Assets Module) — أسبوع
- CRUD كامل للأصول (Livewire components)
- صفحة تفاصيل الأصل (تعرض تاريخ الصيانة بتاعه)
- رفع صور للأصول
- البحث والفلترة (حسب الموقع، التصنيف، الحالة)

### المرحلة 3: أوامر الشغل (Work Orders Module) — أسبوعين
- إنشاء أمر شغل (عطل / صيانة وقائية)
- تعيين فني + تغيير الحالة (Kanban-style أو جدول)
- المرفقات والتعليقات على أمر الشغل
- حساب التكلفة تلقائيًا من قطع الغيار المستخدمة
- إشعارات عند التعيين وعند اقتراب الموعد

### المرحلة 4: الجدولة الوقائية (Preventive Scheduling) — أسبوع
- إنشاء جداول صيانة دورية لكل أصل
- Laravel Command يشتغل يوميًا (Scheduler) يفحص next_due_date ويولّد أوامر شغل تلقائيًا
- تنبيهات قبل الموعد بفترة محددة

### المرحلة 5: المخازن وقطع الغيار (Inventory Module) — أسبوع
- CRUD لقطع الغيار والموردين
- ربط قطع الغيار بأمر الشغل مع خصم الكمية تلقائيًا
- تنبيه لما الكمية توصل للحد الأدنى

### المرحلة 6: التقارير والداشبورد (Reports & Dashboard) — أسبوع
- داشبورد رئيسي: عدد الأعطال المفتوحة، الصيانات المتأخرة، أكثر الأصول أعطال
- تقرير تكلفة الصيانة (شهري / لكل أصل / لكل قسم)
- تقرير وقت التعطل (Downtime) لكل أصل
- تصدير التقارير PDF / Excel

### المرحلة 7: الصلاحيات والتحسينات النهائية — أسبوع
- ضبط صلاحيات كل دور بدقة (مين يشوف إيه، مين يعدل إيه)
- تسجيل العمليات (Activity Log)
- اختبار شامل (Testing)
- تحسين الأداء (Indexes على قاعدة البيانات، Eager Loading)

### المرحلة 8: النشر (Deployment) — 2-3 أيام
- إعداد سيرفر (VPS / Shared Hosting يدعم Laravel)
- ضبط Queue Worker + Scheduler (Cron Job) على السيرفر
- SSL + Backup تلقائي لقاعدة البيانات
- تدريب المستخدمين النهائيين في الشركة

**إجمالي الوقت التقريبي:** 8-10 أسابيع لفرد واحد يعمل بدوام كامل (ممكن يقل لو الفريق أكتر من شخص)

## 6. الصلاحيات المقترحة (Roles & Permissions)

| الدور | الصلاحيات |
|---|---|
| Admin | كل شيء + إدارة المستخدمين والإعدادات |
| Supervisor | إنشاء/تعديل أوامر الشغل، تعيين فنيين، مشاهدة كل التقارير |
| Technician | مشاهدة أوامر الشغل المعينة له فقط، تحديث الحالة، إضافة ملاحظات |
| Viewer | مشاهدة فقط (تقارير وداشبورد بدون تعديل) |

## 7. خطة الاختبار (Testing Plan)

- **Unit Tests:** حساب next_due_date، حساب duration_minutes، حساب التكلفة الإجمالية
- **Feature Tests:** إنشاء أمر شغل، تعيين فني، تغيير الحالة، خصم كمية قطع الغيار
- **Authorization Tests:** التأكد إن كل دور يشوف/يعدل بس اللي مسموح له بيه

---

## 8. نقاط قرار مفتوحة (تحتاج تأكيد قبل البدء الفعلي)

1. هل هيبقى فيه Multi-tenancy (أكتر من فرع منفصل تمامًا) ولا فرع واحد بس؟
2. هل الفنيين هيستخدموا النظام من الموبايل كمان؟ (لو أيوه، لازم نراعي تصميم متجاوب Responsive من الأول)
3. هل محتاجين ربط مع نظام محاسبي أو ERP موجود في الشركة؟
4. هل التقارير المطلوبة محددة (أشكال معينة) ولا استنتجناها؟
